# Совместимость

Коротко: **если ваш регистратор говорит по DVRIP на порту 34567 — BelEye почти наверняка покажет
ваши камеры.** Если у вас только отдельные IP-камеры, подойдёт любая, умеющая RTSP.

Эта страница намеренно различает, что *проверено*, что *вероятно*, а что *не работает*.
Обещать лишнего здесь — значит впустую потратить ваш вечер.

## Проверить своё устройство за 60 секунд

Знать бренд не нужно. Три проверки, по убыванию надёжности:

**1. Открыт ли DVRIP?** В той же сети:

```bash
nc -vz 192.168.1.108 34567      # подставьте IP своего регистратора
```

`succeeded` / `open` → устройство говорит по протоколу, который BelEye использует для
регистраторов.

**2. Настраивается ли он через мобильное приложение, где устройство добавляют по IP и порту
34567 либо по ID / QR-коду?** Такие приложения работают с устройствами на технологии Xiongmai (XM)
*независимо от бренда на корпусе*, а 34567 — порт прямого подключения. Если в инструкции описан
такой сценарий, вы в нужном семействе.

**3. Просто попробуйте.** Добавьте регистратор в BelEye → **Проверить соединение**. Программа либо
войдёт и покажет список каналов, либо честно скажет, что именно не получилось.

> **Чип не имеет значения — важна прошивка.** В объявлениях пишут «чип Mstar», «HiSilicon»,
> «Novatek». О совместимости это не говорит ничего. Тот же чип с прошивкой в стиле Hikvision не
> заработает, а другой чип с прошивкой Xiongmai/Sofia — заработает. Судите по протоколу и порту,
> никогда по чипу.

## Регистраторы (NVR / DVR / HVR)

BelEye говорит по протоколу **DVRIP** (он же *Sofia*) на TCP-порту **34567** — том самом, который
эти регистраторы используют для прямых подключений. Hangzhou Xiongmai — OEM-производитель,
поставляющий начинку более чем сотне сторонних брендов и почти ничего не продающий под своим
именем. Поэтому один протокол покрывает очень большую долю бюджетного рынка: множество безымянных
4/8/16-канальных PoE-регистраторов с AliExpress, Amazon и eBay — это одна и та же прошивка под
разными логотипами.

| Уровень | Что | Почему мы так считаем |
|---|---|---|
| ✅ **Проверено на железе** | **Xiongmai NBD80S16S-KL**, прошивка `V4.03.R11`, 8-канальный PoE HVR — живое видео, архив, календарь, шкала времени, экспорт в mp4, индикатор записи, скорость ¼×–8× | Это устройство, под которое BelEye и разрабатывается. Каждая функция проверена на нём. |
| 🟢 **Очень вероятно — живое видео** | Другие регистраторы на DVRIP | Ключевые вещи общие для всей платформы: 20-байтный заголовок пакета, вход по MD5-хешу `sofia_hash` и поток `OPMonitor`. Определение каналов перебирает **шесть** диалектов прошивок, прежде чем сдаться. |
| 🟡 **Может потребовать доработки — архив** | Другие DVRIP-регистраторы, воспроизведение записей | Архив — то место, где прошивки расходятся сильнее всего, и наш подогнан под устройство выше: данные приходят на опкоде `1422`, тогда как эталонная реализация описывает `1426`; порядок claim/start — `1413 → 1410`, обратный «очевидному»; `OPFileQuery` молча обрезает ответ на 64 записях. Другой прошивке могут понадобиться правки. |
| ❌ **Не поддерживается** | **Регистраторы** Hikvision, Dahua, Uniview, Reolink, Axis, Hanwha | У каждого свой закрытый протокол (Hikvision ISAPI/SDK на 8000, Dahua на 37777, …). С DVRIP общего нет. Их **камеры** — пожалуйста, см. ниже. |

**Количество каналов.** BelEye поддерживает столько, сколько сообщает регистратор, и показывает
порты, к которым реально подключена камера. На 8-канальном устройстве с четырьмя камерами вы
увидите четыре плитки — пустые порты скрыты намеренно, а не потеряны.

**Если ваш регистратор не заработал,** заведите issue со строкой лога, начинающейся с
`[NVR] discovery`, и результатом проверки выше. Определение каналов — самая вероятная точка, где
нужен ещё один диалект, и обычно это небольшая правка.

## IP-камеры (без регистратора)

**Подойдёт любая камера с RTSP** — Hikvision, Dahua, Reolink, Uniview, TP-Link, Amcrest,
безымянная. BelEye собирает обычный RTSP-адрес и отдаёт его FFmpeg, который берёт на себя
авторизацию Basic/Digest и оба кодека, H.264 и H.265.

Единственное, что нужно указать самому, — **путь потока**, потому что автопоиска по ONVIF пока
нет. Типичные пути:

| Производитель | Обычный RTSP-путь |
|---|---|
| **Xiongmai / DVRIP** | `/user=admin&password=PASS&channel=1&stream=0.sdp` — `stream=0` основной, `stream=1` дополнительный ✅ *проверено* |
| Hikvision (и Annke) | `/Streaming/Channels/101` основной, `/102` дополнительный |
| Dahua (и Amcrest) | `/cam/realmonitor?channel=1&subtype=0` |
| Reolink | `/h264Preview_01_main`, `/h264Preview_01_sub` |
| Uniview | `/media/video1` |
| TP-Link Tapo | `/stream1` основной, `/stream2` дополнительный |

Проверена нами только первая строка; остальные — общеизвестные значения по умолчанию для этих
производителей, они могут отличаться в зависимости от модели и прошивки. Истина — инструкция к
вашей камере или её веб-интерфейс. Если путь неверный, проверка соединения так и скажет, а не
промолчит.

**TCP или UDP?** Оставляйте **TCP**, если нет причин поступить иначе. TCP переживает потери в
Wi-Fi и работает через NAT; UDP предусмотрен потому, что у части камер сломана передача по TCP, и
потому что на чистой проводной сети задержка чуть ниже. Учтите: RTSP-серверы некоторых
регистраторов отвечают только по TCP — проверенный Xiongmai как раз такой, так что если вы
подключаетесь к RTSP-порту *регистратора*, используйте TCP.

## Чего нет

Пишем прямо, чтобы вы могли решить до установки:

- **ONVIF** — нет ни автопоиска камер в сети, ни автоматического определения RTSP-пути. Путь
  вводится руками.
- **PTZ** — управления поворотом и зумом нет.
- **Звук** — только видео, и в живом просмотре, и в архиве.
- **Двусторонняя связь**, тревожные входы/выходы и настройка самого устройства (расписание записи,
  зоны детекции) — для этого используйте веб-интерфейс регистратора.
- **Просмотр событий по детекции движения / лиц / автомобилей** — детекции регистратора не
  выводятся отдельным списком. BelEye показывает индикатор записи и подсвечивает в календаре дни,
  где есть записи по событиям, но фильтровать по типу события не умеет.

ONVIF — самое востребованное из этого списка и то, что сильнее всего расширило бы поддержку; но
ни к какому релизу он не обещан.

## Проверенное устройство целиком

Считано с самого устройства по DVRIP, а не взято из объявления:

| | |
|---|---|
| Модель | `NBD80S16S-KL` |
| Прошивка | `V4.03.R11.C6380233.12201.140000.0000000` (сборка 2023-04-14) |
| Тип | HVR, 8 каналов (`DigChannel: 8`) |
| Кодирование | H.265 / H.264, два потока (основной + дополнительный) |
| Детекция | движение, потеря видео, засветка камеры, лица, люди, автомобили |
| Сеть | RTSP, DDNS, NTP, FTP, почта, UPnP, P2P |

Продаётся как *«8-канальный PoE видеорегистратор для IP-камер, 8МП/5МП/4МП/2МП, H.265, обнаружение
лиц, людей, автомобилей»* — ровно та формулировка, которую используют десятки объявлений на одно и
то же железо.
