# BelEye

**Современная программа для китайских видеорегистраторов и IP-камер — без облака.**

Подключите регистратор Xiongmai/DVRIP по IP — и увидите все каналы.
Или добавьте любую RTSP-камеру. Видео не покидает вашу сеть.

Linux · Windows · macOS — бесплатно и с открытым кодом (MIT)

[Совместимость](docs/COMPATIBILITY.md) · [Использование](docs/USAGE.md) · [Архитектура](docs/ARCHITECTURE.md) · [English](README.md)

## Какую проблему это решает

Вы купили 8-канальный PoE-регистратор на AliExpress. Он работает — а вот софт к нему нет.
В комплекте идёт программа только под Windows, выглядящая как из 2013 года, и мобильное
приложение, которое гонит ваше видео через облачный сервер в другой стране. Клиента под Linux, как
правило, нет вообще, а у облачных P2P-функций бюджетных регистраторов давняя публичная история
проблем с безопасностью.

**BelEye — локальная альтернатива.** Один IP-адрес на входе, все ваши каналы на выходе. Без
аккаунта, без облака, без телеметрии. Видео не уходит за пределы вашей локальной сети.

## Заработает ли с моим регистратором?

**Если у вас регистратор из этого семейства — почти наверняка заработает.** Проверка за десять секунд:

```bash
nc -vz 192.168.1.108 34567     # IP вашего регистратора
```

Порт открыт — значит, устройство говорит по протоколу **DVRIP** (он же *Sofia*) — тому самому,
на котором работают штатные мобильные приложения к таким регистраторам, и на котором говорит
BelEye. Hangzhou Xiongmai — это OEM-производитель, поставляющий начинку **более
чем сотне** сторонних брендов и почти ничего не продающий под своим именем. Поэтому один протокол
покрывает огромную долю бюджетного рынка: большинство безымянных 4/8/16-канальных PoE-регистраторов
с AliExpress, Amazon и eBay — это одна и та же прошивка под разными логотипами.

> **Не смотрите на чип.** В объявлениях пишут *Mstar*, *HiSilicon*, *Novatek*. Это ничего не
> говорит о совместимости — её определяет **прошивка**, а не кремний. Тот же чип с прошивкой в
> стиле Hikvision не заработает, а другой чип с прошивкой Xiongmai — заработает.

| | Поддержка |
|---|---|
| **Регистраторы Xiongmai / DVRIP** — NVR, DVR, HVR, PoE, 4/8/16 каналов | ✅ Живое видео, архив, экспорт |
| **Любая IP-камера с RTSP** — Hikvision, Dahua, Reolink, Uniview, TP-Link, безымянные | ✅ Живое видео |
| **Регистраторы** Hikvision / Dahua / Uniview | ❌ Закрытые протоколы, не поддерживаются |

Проверено на железе: **Xiongmai NBD80S16S-KL**, 8-канальный PoE HVR, прошивка `V4.03.R11`, H.265,
с детекцией лиц, людей и автомобилей — продаётся под десятками разных названий.
Подробности и честные оговорки: **[docs/COMPATIBILITY.md](docs/COMPATIBILITY.md)**.

## Возможности

**Регистраторы (DVRIP / Sofia)**
- **Один IP — все камеры.** Подключаете регистратор, список каналов определяется сам. Не нужно
  прописывать RTSP-путь и пароль для каждой камеры отдельно.
- **H.265 и H.264** в реальном времени, декодирование через FFmpeg.
- **Архив** — календарь с подсветкой дней, в которые велась запись, список файлов за день и
  24-часовая шкала: кликом можно перейти в любой момент суток.
- **Скорость воспроизведения от ¼× до 8×**, пауза и точная перемотка.
- **Экспорт в mp4** — сохранение фрагмента копированием потока: без перекодирования, без потери
  качества, без нагрузки на процессор.
- **Индикатор записи** — красный значок на каналах, которые регистратор пишет прямо сейчас.
- **Качество следует за вниманием.** В сетке используются суб-потоки, чтобы не грузить регистратор
  и сеть; при разворачивании камеры она переключается на полный поток **не прерывая картинку**.
  Одна кнопка на панели держит все камеры в высоком качестве, если вам так удобнее.

**IP-камеры (RTSP)**
- Работает с любой RTSP-камерой, H.264 или H.265, по TCP или UDP.
- Понятные ошибки прямо на плитке — `401 Unauthorized`, `Connection refused`, `timed out` —
  вместо чёрного прямоугольника.

**Общее**
- **Автоматическая сетка** — 1, 2×2, 3×3, 4×4…; двойной клик разворачивает камеру.
- **Перетаскивание плиток** мышью — и для каналов регистратора, и для отдельных камер.
- **Автопереподключение** с нарастающей паузой, плюс сторожевые таймеры, которые ловят поток,
  замолчавший без разрыва соединения.
- **Одна сбойная камера не вешает программу** — всё построено на событиях, интерфейс не блокируется.
- **Светлая и тёмная темы**, по умолчанию — как в системе.
- **Пароли в системном хранилище** (GNOME Keyring, KWallet, macOS Keychain, Windows Credential
  Manager), а не в конфигурационном файле.

## Установка

Нужны **Python 3.11+** и **FFmpeg** в `PATH`.

| ОС | FFmpeg |
|----|--------|
| Arch / Manjaro | `sudo pacman -S ffmpeg` |
| Debian / Ubuntu | `sudo apt install ffmpeg` |
| Fedora | `sudo dnf install ffmpeg` |
| macOS | `brew install ffmpeg` |
| Windows | [сборки gyan.dev](https://www.gyan.dev/ffmpeg/builds/) — добавьте `bin/` в PATH |

```bash
git clone https://github.com/belkaniacode/BelEye.git
cd BelEye
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

В Linux скрипт `./install-desktop.sh` добавит BelEye в меню приложений вместе с иконкой.

> **Wayland:** если видео отображается некорректно, переключитесь на X11:
> `QT_QPA_PLATFORM=xcb python main.py`

## Добавить регистратор

**⚙ Настройки → Добавить NVR** → хост, порт `34567`, логин, пароль → **Проверить соединение**.
Каналы появятся сами. На 8-канальном устройстве с четырьмя подключёнными камерами вы увидите
четыре плитки — пустые порты скрываются намеренно.

## Добавить отдельную IP-камеру

**⚙ Настройки → Добавить камеру** → хост, порт `554`, учётные данные и **путь потока**, который у
каждого производителя свой (`/Streaming/Channels/101` у Hikvision,
`/cam/realmonitor?channel=1&subtype=0` у Dahua и так далее — см.
[шпаргалку](docs/COMPATIBILITY.md#ip-cameras-without-a-recorder)).
Транспорт оставьте на `tcp`, если нет причин поступить иначе.

Автопоиска по ONVIF пока нет, поэтому путь придётся вписать вручную.

## Горячие клавиши

| Клавиша | Действие |
|---------|----------|
| `F11` | Полный экран |
| `Esc` | Выйти из полного экрана / вернуться к сетке / отменить перетаскивание |
| `Ctrl+G` | Переключить сетку ↔ одну камеру |
| Двойной клик | Развернуть камеру |
| Правый клик | Изменить / Переподключить / Архив / Удалить |

## Если что-то не работает

**Регистратор не подключается.** Проверьте `nc -vz <ip> 34567`. Если порт закрыт — устройство не
на DVRIP, либо порт изменён в его настройках.

**Каналы не определяются.** Запустите с `BELEYE_LOG_LEVEL=DEBUG` и найдите строки `[NVR] discovery`.
BelEye перебирает шесть диалектов прошивок; если вашей нужен седьмой — заведите issue с этой
строкой лога, обычно это небольшая правка.

**RTSP-камера не играет.** Почти всегда дело в пути. Сверьтесь с инструкцией к камере и проверьте
напрямую через FFmpeg:
`ffmpeg -rtsp_transport tcp -i "rtsp://user:pass@ip:554/path" -t 3 -f null -`

**Рвётся видео по Wi-Fi.** Оставьте транспорт `tcp`. У части регистраторов RTSP-сервер отвечает
только по TCP — проверенный Xiongmai как раз из таких.

**Логи:** `~/.local/state/beleye/beleye.log` (Linux), `~/Library/Logs/beleye/beleye.log` (macOS),
`%LOCALAPPDATA%\beleye\Logs\beleye.log` (Windows).

## Настройки и данные

- Камеры и регистраторы: `~/.config/beleye/cameras.json`, `nvrs.json` — **без паролей**
- Пароли: системное хранилище, имя службы `beleye`

## Как помочь проекту

Самое ценное — **отчёт о совместимости**: модель вашего регистратора, строка прошивки и то,
заработали ли живое видео и архив. Именно так растёт список поддерживаемых устройств.
